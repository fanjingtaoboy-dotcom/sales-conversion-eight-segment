# Offer and Proof Audit

## Core Rule

销讲结构不是只靠话术成立，还要靠 offer 和证据链成立。诊断时同时判断“怎么说”和“凭什么说”：课程主价值、服务机制、赠品权益、价格理由、案例证据和行动路径是否共同支撑购买判断。

## Offer Inventory Card

Use this card when the user provides product, price, bonus, case, or action-path information:

```text
主产品/课程：
核心承诺边界：
解决的具体问题：
课程模块或服务组成：
交付机制：直播 / 录播 / 回放 / 作业 / 答疑 / 社群 / 助教 / 老师点评
价格：原价 / 现价 / 定金 / 尾款 / 分期
优惠理由：
赠品/权益：
每个赠品解决什么问题：
领取条件：
行动路径：链接 / 助教 / 私信 / 表单 / 预约
售后/退款/协议：
案例素材：
证据来源：截图 / 学员反馈 / 数据 / 老师观察 / 用户口述 / 暂缺
```

## High-Ticket Service Stack

For near-3000-yuan and few-thousand-yuan offers, especially from 0元表单、免费营、结缘营 or 福利课 leads, judge whether the offer is presented as a service system.

```text
内容系统：模块、顺序、能力结果
陪伴系统：老师、助教、班主任、答疑、作业反馈
练习系统：实操、打卡、纠偏、复盘
资料工具：讲义、图谱、工具、回放、复训
交付组合：线上、线下、社群、私域、长期服务
售后保障：退款、协议、保价、服务期、适配边界
行动承接：全款、定金、咨询、预约、助教跟进
```

If the service stack is vague, do not treat a high-ticket offer as fully supported even when many bonuses are listed.

## Low-Ticket Offer Clarity

For tens-yuan offers, judge whether the learner can understand and act within seconds.

```text
低价产品：资料包 / 体验课 / 福利课 / 入门营 / 付费占位
价格：原价 / 现价 / 是否全返 / 是否抵扣
到手权益：课程、书籍、工具、回放、社群、答疑、包邮
领取路径：支付后谁联系、地址给谁、什么时候发、如何进课
返还规则：条件、方式、时间、失败情况
低价理由：周年、福利、体验、平台补贴、老师公益、限时活动
```

Low-ticket offers do not need a large service stack, but they need clean rules. If the learner cannot explain "pay what, get what, when, from whom, and how to refund/claim", `优惠政策` is not complete.

## Evidence Stack

Strong conversion normally needs a four-layer evidence stack:

```text
价值主张 -> 作用机制 -> 证明材料 -> 行动路径
```

| 层级 | 检查问题 | 不合格信号 |
|---|---|---|
| 价值主张 | 课程到底帮学员解决什么具体问题 | 只说课程系统、老师厉害、内容很多 |
| 作用机制 | 为什么这个课程能解决这些问题 | 没有流程、练习、反馈、服务、案例路径 |
| 证明材料 | 有什么可信材料支持这个判断 | 只有口号、截图堆叠、极端个案 |
| 行动路径 | 学员下一步怎么做，成本多低 | 链接/助教/定金/预约规则不清 |

## Live Room Handoff Card

训练营销讲常由主讲老师、助教、班主任、场控共同完成。诊断时要拆角色，不要只看主讲话术。

```text
主讲老师：负责问题唤醒、方案承接、价值塑造、情绪推动、顾虑解释。
助教/班主任：负责报名步骤、信息填写、支付提醒、进群/发资料/服务承接。
场控：负责链接、库存/名额状态、评论区提醒、报名播报。
```

合格的助教承接必须包含：

1. 当前 offer 复述：课程/价格/赠品/名额/截止。
2. 清晰步骤：点哪里、填什么、勾选什么、如何提交、如何支付。
3. 常见错误提醒：信息没填、订单超时、价格没确认、赠品地址漏填。
4. 支付后承接：谁联系、进哪个群、什么时候开班、资料/回放/赠品怎么发。
5. 未支付承接：定金、咨询、找助教或下次班期规则。

如果助教只催促“赶紧拍/赶紧付”，但没有降低操作阻力，不能判为行动路径合格。

## Bonus and Rights Judgment

赠品和权益不是越多越好。判断顺序：

1. 是否和主问题相关。
2. 是否解决一个具体行动阻力。
3. 是否有清楚领取条件。
4. 是否不盖过主课程价值。
5. 是否不会制造合规或虚假价值问题。

## Proof Hierarchy

Use proof strength to decide how firm the diagnosis or rewrite can be:

| 证据强度 | 类型 | 用法 |
|---|---|---|
| 强 | 可脱敏真实案例、可核验反馈、清楚前后变化、学习路径完整 | 可作为案例佐证核心 |
| 中 | 评论区反馈、作业截图、社群互动、老师观察 | 可作为辅助信任材料，需要边界表达 |
| 弱 | 泛泛好评、无法核验截图、极端个案、内部口述 | 只能谨慎使用，不能支撑强承诺 |
| 缺失 | 没有案例或数据 | 诊断为案例证据不足，建议补素材 |

## Proof Matrix for Free-Entry High-Ticket

When a free-entry learner is asked to buy a high-ticket course, require more than one proof type:

| 证据类型 | 证明作用 | 检查点 |
|---|---|---|
| 免费体验反馈 | 证明前置体验真实有效 | 是否来自听课、作业、实操、互动 |
| 相似学员案例 | 证明目标学员能代入 | 年龄、基础、问题、顾虑是否相似 |
| 学习过程证据 | 证明结果来自课程机制 | 是否展示练习、反馈、陪伴、复盘 |
| 服务承接证据 | 证明报名后有人管 | 助教/老师/班主任如何响应 |
| 多场景案例 | 证明课程不是只解决单点问题 | 不夸大、不泛化到所有问题 |
| 现场行动信号 | 证明有人正在咨询或报名 | 只能辅助，不能替代真实案例 |

The report should state which proof types are present, missing, or too risky to use.

## Offer-Structure Fit

| 问题 | 对应结构 |
|---|---|
| 主产品价值不清 | 价值塑造会弱 |
| 赠品作用不清 | 优惠政策会弱 |
| 价格理由不清 | 报出价格会弱 |
| 服务容量不清 | 制造稀缺会弱 |
| 学习支持不清 | 降低顾虑会弱 |
| 案例素材不清 | 案例佐证会弱 |
| 行动路径不清 | 优惠政策和案例收口都会弱 |
| 主讲和助教分工不清 | 学员心动但提交失败或不知道下一步 |
| 定金规则不清 | 钱不够的顾虑暂时降低，但后续纠纷风险上升 |

## Rewrite Guardrails

- Do not invent bonuses, refund rules, service promises, teacher credentials, proof screenshots, sales numbers, or case outcomes.
- When proof is missing, write a placeholder and specify the needed evidence.
- Convert offer weaknesses into material requests, not fake copy.
- For high-ticket offers, distinguish “buy now” from “book consult / pay deposit / qualify first”.
