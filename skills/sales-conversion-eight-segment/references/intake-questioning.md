# 前置追问机制

## Core Rule

追问的目标不是收集所有信息，而是拿到会显著改变诊断、评分或改稿的关键前提。不要每次都先问完整表格；根据用户请求强度分层处理。

```text
资料够 -> 直接做
资料不够但可推断 -> 先暂判，标注推断，再问少量问题
缺少关键阻断项 -> 先问 3-5 个问题，再做正式评分或完整改稿
```

## Three Intake Levels

| 使用层级 | 适用场景 | 追问策略 | 输出策略 |
|---|---|---|---|
| 快速诊断 | 用户说先看、粗评、快速判断，或只给短片段 | 不先追问，最多在结尾问 3 个最影响判断的问题 | 给暂判、最大问题、优先改法，标注推断 |
| 标准诊断 | 用户给了销讲稿/大纲，希望诊断或优化 | 如果产品、价格、转化目标、目标学员大体可推断，就先做；缺关键项时问 3-5 个 | 输出学员卡、八段识别、关键缺口、补充清单 |
| 正式评分/完整改稿 | 用户要求打分、为什么不能更高、逐字稿深改、给讲师使用 | 缺阻断项时先问，不要假装能给稳定结论 | 等补充后再给正式分数或完整可讲稿 |

## Blocking Information

正式评分至少需要：

```text
销售产品/课程：
价格或价格档位：
转化目标：
目标学员或学员场景：
销讲材料：大纲 / 逐字稿 / 片段 / 口播内容
```

完整改稿最好还需要：

```text
刚刚交付的教学内容：
学员当前心理状态：
学员已相信什么、未相信什么：
主要行动阻力：
课程核心价值点：
赠品/权益：
学习服务机制：
售后/退款/保障规则：
真实案例素材：
报名路径：
合规限制：
讲师表达风格或保留要求：
最终给谁看：自己 / 课程顾问 / 教研 / 讲师
```

## Minimum Five Questions

如果只能问 5 个，优先问：

1. 这场销讲要卖什么，价格是多少？
2. 转化目标是什么：全款、定金、加微信、预约诊断、进群、续报还是升单？
3. 目标学员是谁，刚刚听完什么教学内容？
4. 学员此刻已经相信什么、还没有相信什么？
5. 学员不行动的最大阻力是什么？

## Question Selection Logic

| 缺少的信息 | 会影响什么判断 | 优先级 |
|---|---|---|
| 产品和价格 | 价格决策难度、结构权重、转化目标是否合理 | 最高 |
| 转化目标 | 行动路径、报价策略、高客单是否应咨询/定金承接 | 最高 |
| 目标学员 | 问题唤醒是否共性、案例是否相似 | 最高 |
| 刚刚教学内容 | 教学获得感到问题唤醒的衔接 | 高 |
| 已相信/未相信 | 方案承接、价值塑造、顾虑处理 | 高 |
| 主要阻力 | 降低顾虑、案例佐证、优惠政策 | 高 |
| offer 和赠品权益 | 价值塑造、优惠政策、价格接受 | 中高 |
| 售后/保障规则 | 降低顾虑、合规边界 | 中高 |
| 案例素材 | 案例佐证、信任闭环 | 中高 |
| 转化率目标 | 迭代方向和业务目标，不直接决定结构分 | 中 |

## Conversion Rate Targets

转化率目标有价值，但不能替代结构诊断。它受流量质量、信任基础、价格、offer、讲师状态、助教承接、活动力度影响。

如果用户提供或询问转化率目标，优先追问：

```text
历史转化率是多少：
这次目标转化率是多少：
样本量大概多少：
流量来源/学员来源：
当前怀疑的卡点：听不下去 / 觉得不值 / 不敢买 / 不知道怎么行动 / 其他
```

Use conversion rate as context for prioritizing fixes:

| 卡点 | 优先检查 |
|---|---|
| 听不下去 | 问题唤醒、教学到销讲衔接、相关力 |
| 觉得不值 | 方案承接、价值塑造、价格锚定 |
| 不敢买 | 降低顾虑、售后保障、案例证据 |
| 不知道怎么行动 | 优惠政策、报名步骤、行动指令 |
| 只问价格 | 价值塑造和价格锚定不足 |

## How to Ask

Use concise, non-blocking language:

```text
我可以先基于现有材料做暂判，但要做正式评分/完整改稿，还差 3 个关键前提：
1.
2.
3.
```

Avoid asking the full checklist unless the user explicitly asks for a template.

## When Not to Ask First

Do not ask first when:

- 用户明确要求快速判断。
- 原稿已经足够支持核心问题判断。
- 用户只问“这个方向是否合理”。
- 用户要求先基于现有材料推断。
- 追问不会改变当前最明显的结构结论。

In these cases, answer first, then list missing inputs that would improve the next version.
