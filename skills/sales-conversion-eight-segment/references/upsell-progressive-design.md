# 转阶进阶销讲设计

## Core Rule

本文件只处理“阶段升级/转阶/续报/升单”这一类应用场景。先使用 `conversion-structure-principles.md` 的原理、原则和方法，再判断本场转阶逻辑。不要把具体行业案例当成主规则。

一阶转二阶、基础班转进阶班、入门营转进阶营、老学员续报升单，不是把“下一门课内容更多”说清楚就够了。它的核心是证明：

```text
上一阶段已经帮你完成了 A
但要进入真实应用/更高结果，还会卡在 B
解决 B 需要一套你本来就容易认可的标准 C
下一阶段课程正好按 C 来交付
所以继续学不是重复购买，而是进入下一层能力
```

诊断这类销讲时，先判断“转阶逻辑”是否成立，再按八段检查。

## Stage Upsell Card

诊断或设计转阶销讲前，先建立这张卡：

```text
前一阶段课程：
前一阶段已交付能力：
学员已获得的确认感：
前一阶段留下的下一层缺口：
下一阶段课程：
下一阶段核心升级主张：
转化目标：全款 / 定金 / 咨询 / 预约 / 入群
价格档位：
主目标人群：
次目标人群：
学员最容易认可的正确标准：
产品如何符合这个标准：
现有证据：前一阶段反馈 / 下一阶段案例 / 机制演示 / 老师经验 / 暂缺
主要顾虑：重复学习 / 学不会 / 不适合 / 贵 / 时间 / 直接跳线下或高阶
```

If this card is mostly unknown, give a provisional diagnosis and list the few missing fields that most affect judgment.

## Consensus Progression

转阶销讲的前三段必须从“用户已经认可的共识”递进，而不是从产品自卖自夸开始。

### 问题唤醒：共识型问题

提出的问题应满足：

1. 学员本来就认可，不需要辩论。
2. 覆盖主目标人群中的多数人。
3. 能从前一阶段学习自然长出来。
4. 能留下下一阶段入口。
5. 不把“我要买下一门课”伪装成问题。

推荐递进：

```text
泛共识问题 -> 专业学习问题 -> 真实应用/结果问题
```

例：

```text
不是“你需要报名进阶课”，
而是“只会一个基础判断，还不足以在真实场景里稳定给出判断和表达。”
```

### 方案承接：先标准，后产品

方案承接不能直接说“我们的课程就是解决方案”。应先说学员容易认可的方法标准：

```text
要解决前面的问题，需要什么样的能力/方法/训练标准？
这个标准为什么能解决问题？
学员是否会自然点头？
我们的产品如何符合这个标准？
```

不合格信号：

- 从问题直接跳到课程名。
- 只说“进阶课更系统、更深入”，没有标准。
- 用太专业的概念替代用户可理解的解决原则。

### 价值塑造：产品符合标准

价值塑造要证明“课程怎么把方案标准落地”，而不是罗列目录。

最低结构：

```text
模块/服务 -> 解决什么具体问题 -> 用什么机制解决 -> 学员得到什么结果感
```

## Claim Chain Check

一句核心卖点必须能拆成连续因果链。否则容易变成口号。

```text
能力提升 -> 判断更稳 -> 表达更可信 -> 学员/顾客更信任 -> 交付或经营结果改善
```

诊断时检查：

1. 核心主张是否太跳跃。
2. 中间因果是否缺环。
3. 每一环是否有课程机制或证据支撑。
4. 对主目标人群和次目标人群的结果表达是否不同。

例如“能力越强，结果越好”中间通常需要补：

```text
能力更强 -> 判断更准 -> 交付/服务方向更稳 -> 对方更信任 -> 首次成交、复购、口碑或转介绍更有基础
```

对非经营人群，结果链要改成：

```text
能力更强 -> 判断更清楚 -> 个人/团队使用更有方向 -> 学习信心和行动能力提升
```

## Primary and Secondary Audience Rule

转阶产品常同时适合多类人，但销讲不能平均服务所有人。

判断顺序：

1. 先锁定本场最值得成交的主目标人群。
2. 问题唤醒可以覆盖多类人，建立广泛相关。
3. 方案承接要找到多类人都能认可的共同标准。
4. 价值塑造以主目标人群为主。
5. 次目标人群只在最相关的模块轻量承接，不要求每个模块都单独展开。

不合格信号：

- 每个人群都讲一遍，导致主线被打散。
- 前面唤醒了某类人，后面完全没有承接。
- 所有价值都围绕主目标人群，次目标人群突然觉得“这不是给我的”。

可用处理：

```text
主线给主目标人群完整承接；
次人群在 1-2 个高相关模块中点到“你也能用在哪里”；
最后用一句“同一路径，多种应用场景”统一收束。
```

## Scenario Focus

场景不是越多越好。每增加一个场景，就必须在后面有承接成本。

诊断场景设计时检查：

1. 这个场景是否服务主线问题。
2. 是否代表一类目标人群的真实高频情况。
3. 后面方案和价值是否能接住这个场景。
4. 篇幅是否挤压了方案承接、价值塑造和成交动作。

如果时间有限，优先保留：

```text
主目标人群最高频、最痛、最能引出下一阶段价值的场景
```

次要场景可以压缩成一句话，不要平铺。

## Module Value Deepening

进阶课常见误区是把“模块多、课时多、内容细”当价值。正确判断是看每个模块有没有下沉到功能价值。

使用这张核查表：

| 模块 | 表面内容 | 解决的问题 | 交付机制 | 学员拿到的结果感 | 支撑的八段 |
|---|---|---|---|---|---|
| 模块 1 | 学什么 | 补哪个缺口 | 怎么练/怎么教/怎么反馈 | 能做什么判断或动作 | 价值塑造/降低顾虑 |

最低要求：

1. 每个主模块都要对应一个前一阶段未解决的缺口。
2. 模块价值要能用一句话说清。
3. 不能只说“学完更多知识”，要说“拿到什么判断能力、表达能力、应用能力或行动能力”。
4. 服务、答疑、回放、工具包可以放入价值塑造，也可以归入降低顾虑或优惠政策，按功能归位。

## Expertise Product Price Strategy

转阶进阶课常是专业能力产品。价格策略有两种，不要自动选择“显得很便宜”。

| 策略 | 适合情况 | 表达重点 | 风险 |
|---|---|---|---|
| 性价比策略 | 中低价、低阻力、权益清晰 | 平摊成本、优惠力度、付出小 | 可能削弱专业价值 |
| 价值承接策略 | 专业技术、进阶能力、几千元课程 | 技术稀缺、学习成本、系统交付、应用价值 | 需要证据和服务承接 |

专业进阶课可以让学员觉得“并不便宜，但值得”。不要为了降低价格阻力，把高价值技术讲成普通便宜课。

可用锚定：

```text
过去获得类似能力的成本：线下跟学、师承、长期实践、试错、案例复盘
现在课程的系统交付：模块、周期、答疑、练习、工具、案例
学员不学的机会成本：判断不稳、表达不清、服务承接弱、复盘成本高
```

注意：

- 不要虚构线下价格、老师资历、学习成本。
- 不要只靠赠品价值相加支撑价格。
- 如果提到线下班可抵扣、保价、复训、回放，必须确认真实规则。

## Proof When Next-Stage Cases Are Missing

第一期进阶营或新产品常没有直接的下一阶段案例。不能假造案例，也不能把前一阶段案例硬说成下一阶段效果。

可用的过渡证据：

1. 前一阶段学员反馈：证明学员已经有基础获得感。
2. 老师或团队过往交付经验：证明方法来源和经验基础。
3. 机制演示：现场展示下一阶段如何从一个点推到更具体结果。
4. 内部打磨或试讲反馈：证明课程不是临时拼凑。
5. 线下/旧版本经验：如真实存在，可作为产品来源证明。

判定规则：

```text
过渡证据可以支撑“为什么值得试第一期/本期”，
但不能替代下一阶段学员结果案例。
```

如果缺少直接案例，正式评分通常不能给 9 分；应建议开班后系统收集脱敏案例。

## First Cohort Iteration Rule

首次上线或第一期课程，不要要求一次做到最终版，但要区分“本期必须修”和“下期可迭代”。

本期必须修：

1. 核心转阶主张是否清楚。
2. 问题 -> 标准 -> 产品的链路是否顺。
3. 主目标人群是否清楚。
4. 价格、权益、报名路径、服务规则是否真实清楚。
5. 合规边界是否安全。

下期迭代：

1. 真实案例矩阵。
2. 更细的场景分层。
3. 不同人群分支话术。
4. 更准确的转化数据和阻力分析。
5. PPT 展示和逐字稿节奏打磨。

## Script and Slide Boundary

诊断课程开发讨论稿时，先分清：

```text
一级模块：八段结构位置
二级模块：这一段要完成的任务
三级模块：具体观点、场景、例子、页面或话术
PPT 呈现：页面拆分、排版、素材
```

不要把 PPT 页数、版式、单页放几个点，当成结构质量本身。结构诊断先看一级和二级任务；三级观点和 PPT 页面可以后调。

## Rewrite Patterns

### 从上一阶段到下一阶段

```text
上一阶段，我们已经帮大家完成了 X。
但如果你想进入真实应用/更稳定结果，光有 X 还不够，下一步会卡在 Y。
解决 Y，不是再多听几个零散知识点，而是要建立 Z 标准。
这也是下一阶段课程真正要交付给你的东西。
```

### 先标准后产品

```text
什么样的方法才算真正能解决这个问题？
第一，它要能做到 A；第二，它要能做到 B；第三，它还要能帮你 C。
我们这套进阶课的设计，就是围绕这三个标准展开。
```

### 主人群完整承接，次人群轻量承接

```text
如果你是核心应用人群，这一部分直接关系到你的判断、表达和后续承接。
如果你暂时不是核心应用人群，它也会帮你把个人学习和日常应用做得更有方向。
但这门课的主线，还是围绕真实应用场景来训练。
```

### 专业价值价格锚定

```text
过去想获得这样的能力，通常要靠线下训练、导师带教、反复实操和大量案例复盘，成本不只是学费，还有时间和试错。
这次把它整理成系统课程，是为了让你用更清楚的路径先建立能力框架，再进入练习和应用。
```

## Common Misjudgments

| 表面动作 | 容易误判 | 实际判断 |
|---|---|---|
| 讲“二阶更深入” | 方案承接 | 没有说明正确标准 |
| 罗列 15 节课目录 | 价值塑造 | 没有模块价值下沉 |
| 把多类人群都铺开 | 相关性强 | 主线可能被稀释 |
| 只说比线下便宜 | 价格锚定 | 可能降低专业感，且需真实依据 |
| 用一阶反馈证明二阶结果 | 案例佐证 | 只能算过渡证据，不能替代二阶案例 |
| 纠结 PPT 页数 | 结构诊断 | 应先判断一级/二级任务是否成立 |
