# 销讲结构原理与方法

## Core Rule

从真实销讲、逐字稿、复盘讨论中迭代 skill 时，优先提炼“结构原理、判断原则、可复用方法”，不要把具体行业案例、单个产品话术或某次项目经验当成核心能力。

沉淀顺序：

```text
原理 -> 原则 -> 方法 -> 检查项 -> 话术骨架 -> 脱敏样例
```

案例只用于说明和评测，不作为主规则。

## 四层抽象

分析素材时先分四层：

| 层级 | 回答的问题 | 应沉淀到 skill 的形式 |
|---|---|---|
| 原理 | 为什么这一段要这样设计 | 心理推进、结构因果、先后顺序 |
| 原则 | 什么情况算对，什么情况算错 | 判断标准、边界、常见误判 |
| 方法 | 具体怎么设计或改稿 | 步骤、检查表、话术骨架 |
| 案例 | 某个行业/课程里怎么出现 | 脱敏样例、评测样例 |

如果只能保留一层，保留原理和原则；如果要帮助使用者落地，再补方法；案例放最后。

## 结构功能优先

销讲八段是功能链路，不是内容标签。每段先判断它承担什么心理转换，再判断内容是否合适。

通用检查：

```text
这一段让学员从什么状态走到什么状态？
这一步为什么必须发生在下一步之前？
当前内容是否真正完成了这个转换？
如果删掉这一段，后续哪一个购买判断会断？
```

常见误判：

| 表面内容 | 不等于 | 应检查的功能 |
|---|---|---|
| 讲了一个痛点 | 问题唤醒 | 是否唤醒多数目标学员的共性相关 |
| 说课程很适合 | 方案承接 | 是否先建立低抗拒的正确方向 |
| 介绍课程目录 | 价值塑造 | 是否把价值对应到问题和结果 |
| 说名额有限 | 制造稀缺 | 是否有真实机会边界和理由 |
| 报了优惠价 | 报出价格 | 是否建立价格接受链 |
| 送很多东西 | 优惠政策 | 是否讲清作用、条件和行动 |
| 说不用担心 | 降低顾虑 | 是否用机制处理真实阻力 |
| 放了截图 | 案例佐证 | 是否有相似性、路径、结果和行动收口 |

## 共识优先

销讲不是先制造争议再辩赢用户。好的问题唤醒和方案承接，先从学员已经认可或容易认可的事情进入。

原则：

1. 问题唤醒不是让学员质疑，而是让学员点头。
2. 方案承接不是让学员先相信产品，而是先相信正确方向。
3. 用户尚未接受的观点，不能放在链路前面承担基础功能。

检查句：

```text
这句话需要解释很久才能认同吗？
如果需要，它不适合当问题唤醒的起点。
```

## 递进收口

问题唤醒要从宽到窄，而不是一开始就落到产品。

推荐结构：

```text
广泛相关的问题 -> 目标人群的专业/行动问题 -> 当前场景的关键结果问题 -> 方案入口
```

判断标准：

1. 第一层能让多数目标学员觉得相关。
2. 第二层把人群筛到更准确。
3. 第三层把问题推到本场要解决的关键结果。
4. 最后一层自然留下“需要一个正确方案”的入口。

错误路径：

```text
小众场景 -> 产品名 -> 课程目录 -> 价格
```

## 先标准后产品

方案承接的本质是“让学员先认可选择标准”，不是“直接说产品就是答案”。

方法：

```text
要解决 Y，不能只靠 A。
一个合格的方案至少要满足 B、C、D。
为什么 B、C、D 能解决 Y。
接下来再说明：本产品如何按 B、C、D 设计。
```

检查项：

1. 是否先提出正确原则、方法标准或选择标准。
2. 标准是否来自学员已经认可的问题。
3. 标准是否足够具体，能排除低质量方案。
4. 产品是否在标准之后出现。

## 产品承接标准

价值塑造要证明产品符合前面提出的标准。

结构：

```text
标准 1 -> 产品设计 1 -> 解决的问题 -> 结果感
标准 2 -> 产品设计 2 -> 解决的问题 -> 结果感
标准 3 -> 产品设计 3 -> 解决的问题 -> 结果感
```

如果前面提出了标准，后面没有证明产品符合标准，学员会停在“道理我认同，但为什么买你”。

## 价值下沉

价值不是“内容很多”，而是“我能解决什么、怎么解决、拿到什么变化”。

最低下沉链：

```text
内容/模块/服务 -> 功能 -> 机制 -> 结果感 -> 对购买判断的作用
```

检查表：

| 项目 | 要回答的问题 |
|---|---|
| 内容 | 学什么、得什么、包含什么 |
| 功能 | 它解决哪个具体问题或顾虑 |
| 机制 | 通过训练、反馈、工具、服务还是流程解决 |
| 结果感 | 学员学完能做什么、判断什么、表达什么、完成什么 |
| 购买作用 | 支撑价值、降低顾虑、增强行动还是提供证据 |

## 主张链路

核心卖点不能跳跃。所有强主张都要拆成因果链。

模板：

```text
能力变化 -> 行为变化 -> 判断变化 -> 信任变化 -> 结果变化
```

诊断时检查：

1. 主张是否从能力直接跳到收入、效果、成交、改变人生。
2. 中间是否缺少行为、机制或信任环节。
3. 每一环是否有课程机制或证据支撑。
4. 不同人群是否需要不同结果链。

改写方法：

```text
不要只说“学会 X，就能得到 Z”。
要补成“学会 X 后，你会先做到 A；A 稳了，B 才更容易发生；B 发生后，Z 才有基础。”
```

## 主次人群

一个销讲可以覆盖多类人，但不能平均服务所有人。

原则：

1. 主目标人群决定主线、案例、价值塑造和行动目标。
2. 次目标人群可以在问题唤醒中被照顾，但不必每段都展开。
3. 如果前面唤醒了次目标人群，后面至少要给轻量承接。
4. 如果所有人群都完整展开，主线通常会被稀释。

推荐处理：

```text
问题唤醒：广泛覆盖
方案承接：共同标准
价值塑造：主目标人群为主
降低顾虑：补 1-2 个次目标人群关键顾虑
收口：说明主线适配谁，其他人群怎么判断自己是否适合
```

## 场景承接成本

场景不是越多越好。每增加一个场景，就增加后续承接成本。

检查：

1. 这个场景是否代表高频共性问题。
2. 是否能自然推到同一个方案标准。
3. 后面的价值、案例、顾虑是否接得住。
4. 是否挤占了报价、行动路径和顾虑处理时间。

当场景过多时，优先保留最能推动主线的场景，把其他场景压缩为一句归纳。

## 价格策略选择

价格接受不等于“讲得越便宜越好”。价格策略要匹配产品属性和学员心理。

| 策略 | 适用 | 核心表达 |
|---|---|---|
| 低门槛策略 | 低价、体验、占位、冲动购买 | 付出小、风险低、动作简单 |
| 性价比策略 | 中价、权益清晰、信任较好 | 花费可控、权益丰富、值得先上车 |
| 价值承接策略 | 专业能力、系统训练、几千元以上 | 不一定便宜，但比自学、试错、零散解决更值得 |
| 咨询承接策略 | 高价、重决策、适配差异大 | 先评估、先沟通、先锁资格，不强行全款 |

判断标准：

```text
学员是嫌贵，还是怕不值？
是缺优惠，还是缺证据？
是能当场买，还是需要咨询/定金/资格评估？
```

## 证据边界

证据要服务购买判断，也要守住真实边界。

原则：

1. 机制可以证明“为什么可能有效”，不能替代结果案例。
2. 前一阶段反馈可以证明已有信任，不能冒充后一阶段结果。
3. 老师经验可以证明来源，不能直接证明每个学员结果。
4. 截图和好评必须有相似性、路径和边界，才算强证据。

证据分层：

```text
主张 -> 机制 -> 过程证据 -> 相似案例 -> 多案例/从众 -> 行动收口
```

## 诊断颗粒度

诊断讨论稿、逐字稿或课件时，先分清问题属于哪一层：

| 层级 | 关注点 | 处理方式 |
|---|---|---|
| 一级结构 | 八段是否完整，顺序是否合理 | 大改结构 |
| 二级任务 | 每段是否完成心理推进任务 | 调整段落目标 |
| 三级观点 | 观点、场景、例子是否支撑任务 | 增删内容 |
| 话术表达 | 语言是否顺、是否讲师能说 | 改句子 |
| PPT 呈现 | 页面拆分、排版、视觉呈现 | 最后处理 |

不要把 PPT 页数、版式或单页信息量当成结构问题本身。先定结构任务，再定表达和呈现。

## 从反馈提炼规则

当用户提供复盘讨论、沟通录音或对某稿件的反馈时，按这个方法提炼：

```text
1. 找到争议点：他们到底在争什么？
2. 抽掉行业名词：把具体产品、病症、行业动作替换成 X/Y/Z。
3. 判断结构层级：这是一级结构、二级任务、三级观点、话术，还是 PPT 呈现？
4. 提炼原理：它说明了哪条购买心理推进规律？
5. 形成原则：以后什么情况判对，什么情况判错？
6. 形成方法：下次设计或改稿按什么步骤做？
7. 形成检查项：skill 诊断时应该问哪几个问题？
8. 形成评测样例：用脱敏虚构材料测试是否会复现这个判断。
```

输出时使用：

| 原始反馈类型 | 原理提炼 | 原则 | 方法/检查项 | 放入 skill 的位置 |
|---|---|---|---|---|
| 具体讨论点 | 背后的心理或结构规律 | 可复用判断 | 可执行步骤 | SKILL.md / reference / eval |

## 输出要求

当用户要求“提炼进 skill”“优化 skill 能力”“从案例中挖掘规则”时，输出和落库都要遵循：

1. 先给原理级结论，再给案例对应。
2. 先沉淀通用规则，再决定是否保留脱敏样例。
3. 不把行业案例放在核心文件开头。
4. 不把新案例变成新的一级模块。
5. 明确这个规则增强的是哪一段：问题唤醒、方案承接、价值塑造、价格、顾虑、案例，还是跨段咬合。
6. 每个新增规则都要能回答“以后遇到不同产品时怎么用”。
